任务要求：题目 0：互联网视频直播高并发弹幕时间轴对齐缓存
工程背景：在大型网络直播（如顶级电竞赛事直播、跨年晚会）中，高并发弹幕在某
些精彩瞬间会呈现爆发式增长（每秒数万条甚至数十万条）。弹幕服务器接收到来自前端
的弹幕时，由于网络传输抖动、基站切换或客户端重发，弹幕到达服务器的时间戳往往是
严重乱序的。为了保证所有观众在回放或同步观看时，弹幕能与视频画面的绝对时间轴精
确对齐，服务器必须在内存中建立一个高效的滑动的时序缓冲区。该缓冲区需要对乱序到
达的弹幕进行快速的原地插入排序，同时自动切除并释放超出滑动窗口的过期弹幕。此外，
为了防止突发流量冲垮系统，必须严格限制单一时间窗口内的弹幕总量，触发基于权重的
降级丢弃机制。
设计与实现要求：
1.数据结构设计：由学生完全手工实现一个支持快速局部查找与插入的时序表或
带水平索引的双向循环链表。为了避免频繁高频申请/销毁节点带来开销，设
计一个固定的对象池（ObjectPool）。释放的弹幕节点不直接丢弃，而是回收
到池中，新弹幕到达时优先从池中获取。
2.核心算法设计：实现动态滑动窗口更新算法，随着视频时间轴向前推进（模拟
每秒前进1秒），系统需高效切除并回收窗口前（如30秒前）的过期弹幕节
点；新弹幕到达时，根据其自带的视频时间戳，快速定位并插入到正确的位
置，确保整条时间轴有序；当某一秒内的弹幕密度超过预设阈值（如每秒最
多500条）时，触发降级：优先丢弃权重低的弹幕。
3. 设计要求：编写一个单线程弹幕发射器，需成功处理以下边界情况：（1）故
意制造大批延迟了3-5秒的“老弹幕”突发到达，测试系统乱序插入能力；
（2）模拟某段时间没有弹幕输入，窗口依然正常滑动；（3）模拟当弹幕量超
过承载上限时，自动启动丢弃策略。同时，以“带水平索引的双向循环链表”
为目标方法，以传统“标准单链表”为基准方法。在不同数据规模下进行时间
复杂度和空间复杂度性能测试，展示测试结果，绘制时空变化曲线图，并结合
实验数据对两种方法的性能差异及原因进行分析。
4.功能交互可视化：无需实现复杂的底层指针动画，采用更直观的状态与数据可
视化。为该系统搭建一个简易的图像化界面，展示弹幕飘过效果，并实时展
示当前滑动窗口（例如当前在第100秒~130秒之间）的整体结构；以柱状图
或文字块颜色的深浅，实时展示这30个“时间槽”中每一个槽位的弹幕密度
（条数）；当发生“过期节点回收”或“触发限流丢弃”时，在控制台高亮
打印相关日志或触发界面闪烁提示。
具体要求
学生在实现过程中，必须纯手工构建底层核心数据结构，严禁直接调用高级语言内置
的封装集合库（如 Java 的 TreeMap、Python 的 networkx 等）。此外，所有题目均强制要
求开发高质量的功能交互或算法执行可视化面板，以全方位考查学生的数据结构设计能力、
算法实现能力以及工程系统化思维
